Antigravity Project Guide: 1-4 Player Party Games Replica
Technical Architecture, Gameplay Specifications, and Dual-Agent Automation Protocol
1. Executive Summary & Architecture Overview
This specification provides a complete blueprint for developing a high-performance, local same-device 1-to-4 player party game suite using Google Antigravity. Inspired by hit titles like 1 2 3 4 Player Games, this project upgrades the genre with modern visuals, punchy physics, expanded minigame mechanics, responsive touch/keyboard controls, and a dual-agent continuous development and playtesting pipeline.
Recommended Technology Stack
Runtime & Framework: TypeScript with Vite for instant hot-module replacement and rapid bundling.
Rendering Engine: HTML5 Canvas with PixiJS or lightweight 2D WebGL/Canvas rendering to guarantee rock-solid 60 FPS across mobile, tablet, and desktop browsers.
Physics Engine: Matter.js (2D rigid body physics) or lightweight custom arcade physics tailored for hyper-responsive tactile feedback.
Audio: Web Audio API (procedural synthesis / chip-tune sound effects for zero-latency instant feedback without asset load blockers).
Testing & Automation: Playwright with multi-touch pointer emulation, Chrome DevTools Protocol (CDP), and headless/headed browser actuation.
2. Core UI & UX Architecture
2.1 Ergonomic Screen Layout (Shared Tablet / Phone)
The interface is designed for landscape mode (16:9 / 19.5:9 aspect ratios) placed flat on a table between players or held collaboratively:
Player 1 (Red): Top-Left quadrant / corner.
Player 2 (Blue): Top-Right quadrant / corner.
Player 3 (Green): Bottom-Left quadrant / corner.
Player 4 (Yellow): Bottom-Right quadrant / corner.
Input Action Zones
In 1-button games, the entire outer corner area functions as the player's large tap/hold button.
In joystick/steer games, a dynamic floating virtual thumbstick or 2-segment directional rocker appears under the player's finger within their designated corner quadrant.

2.2 Menu System & Flow
Lobby & Player Count Selection:
Prominent toggle buttons: 1 Player (Solo vs CPU), 2 Players, 3 Players, 4 Players.
Active player badges in each corner. Tapping an inactive player badge toggles between Human, Bot (Easy/Normal/Hard), and Disabled.
Game Selector Carousel:
Horizontal swipeable cards featuring high-contrast animated previews, game title, and control iconography (e.g., "1-Tap Tap", "Steer & Boost", "Hold & Release").
Filter tags: All, Action, Racing, Sports, Puzzle/Reflex.
Cup / Tournament Mode:
Configurable tourney length: First to 3 Points, Best of 5, or Custom Game List.
Live podium leaderboard shown between rounds with animated point bars and player celebrations.
In-Game HUD:
Corner indicator lights displaying player score/lives.
Central countdown timer and Sudden Death flash banners.

Round End & Rematch Screen:
Displays victory fanfare, MVP highlights, and corner-accessible "Rematch" and "Next Game" buttons so any participant can restart without rotating the screen.
3. Enhanced Minigame Catalog ("More Better Games")
Game 1: Cyber Tanks 2.0 (Ricochet Arena)
Concept: Upgraded tank duel featuring bouncing laser projectiles, destructible energy crates, and dynamic arena hazards.
Controls: Single button per player. Hold to rotate tank; release to drive forward. Double-tap to fire bouncing projectile.
Upgrades: Power-up crates drop periodically (Shield, Triple-Shot, Bouncing Landmines, Railgun Laser that pierces walls). Explosive barrel chain-reactions.
Win Condition: Last tank standing or most eliminations in 60 seconds.
Game 2: Bumper Hovercrafts (Shrinking Glacier)
Concept: Physics-heavy arena brawler where players ram each other off an icy, crumbling platform into the abyss.
Controls: Tap to burst forward with rocket thrust; turning is automated via centrifugal pendulum or gyro momentum.
Upgrades: The arena breaks apart in concentric rings as the timer runs down. Spawning anvils and speed boosts add unpredictability to momentum collisions.
Win Condition: Last survivor on the remaining iceberg.
Game 3: Laser Grid Reflex (Tile Overcharge)
Concept: 4x4 or 6x6 floor grid where tiles flash telegraphing incoming laser strikes.
Controls: Tap to dash 1 tile in a continuous clockwise/counter-clockwise cycle; hold to reverse direction.
Upgrades: Overcharged golden tiles offer bonus points, forcing risky positioning. Moving laser sweeps and shrinking safe zones as speed increases.
Win Condition: Outlast opponents or gather 10 charge batteries first.
Game 4: Orbital Slingshot (Meteor Miner)
Concept: Space-themed physics game where small spacecraft orbit celestial bodies and slingshot to collect crystals or ram rivals.
Controls: Hold button to tether to nearest gravity well; release to release momentum into a slingshot arc.
Upgrades: Wandering black holes create gravitational distortion. Space debris and EMP power-ups disrupt opponent gravity tethers.
Win Condition: First player to collect 25 space crystals or survive 90 seconds.
Game 5: Micro Turbo GP (Single-Button Drift)
Concept: Top-down micro racer on neon circuit tracks.
Controls: Car drives forward automatically. Hold button to execute a tight power drift; release to straighten and trigger a mini turbo boost.
Upgrades: Slipstreaming mechanic (driving behind a leader grants drafting speed boosts). Track hazards include oil slicks, jump ramps, and moving track barriers.
Win Condition: First across the finish line after 3 laps.
Game 6: Ghost Flashlight (Darkness Tag)
Concept: Top-down dark mansion where players are invisible except when using flashlights or stepping on noisy floorboards.
Controls: Hold to rotate character; release to run. Tap second action (or tap rhythm) to flash light for 0.5s.
Upgrades: One player starts as the "Cursed Ghost" who moves faster in shadows. Tagging another player transfers the curse with an explosive spectral blast.
Win Condition: Human who spent the least time as the Ghost when the 60-second timer expires.
Game 7: Kitchen Chaos (Food Fling)
Concept: Cooperative or competitive culinary frenzy where food items fly across the screen.
Controls: Tap to scoop ingredients from conveyor belts; time release to launch ingredients onto central target plates.
Upgrades: Rotten ingredients cause point penalties and stun opponents if intercepted. Fever mode doubles all points during the final 15 seconds.
Win Condition: Highest recipe score achieved.
Game 8: Skyline Sumo (Springboard Bouncer)
Concept: Vertical platform climbing where players jump across springy scaffolding while knocking each other down.
Controls: Hold to charge jump height and launch angle indicator; release to leap.
Upgrades: Screen scrolls upward continuously—falling off bottom causes instant respawn penalty. Bouncing directly on an opponent's head stuns them and launches you higher.
Win Condition: First player to reach the rooftop trophy or highest climber when time runs out.
4. Dual-Agent Continuous Build & Test Loop in Antigravity
To enable hands-off, automated engineering where one agent builds while another tests and breaks features, configure two coordinated sub-agents communicating through explicit file contracts.
4.1 Orchestration Protocol & Shared Workspace State
Both agents work within the same repository directory and maintain synchronization using three markdown status logs:
ROADMAP.md: Master checklist of features, mini-games, and bug fixes with statuses (TODO, IN_PROGRESS, READY_FOR_TEST, VERIFIED).
BUILD_LOG.md: Updated by Agent 1 (Builder) after every commit or feature build, detailing what was implemented, how to run it, and specific test vectors.
QA_LOG.md: Updated by Agent 2 (Playtester) after executing automated browser tests, logging bug reproductions, console errors, frame drops, and screenshot artifacts.
4.2 Workflow Loop
[Agent 1: Builder]
Picks next TODO from ROADMAP.md
Writes TypeScript/Canvas game logic
Verifies build & TypeScript types pass (npm run build)
Updates BUILD_LOG.md and marks item READY_FOR_TEST
[Agent 2: Playtester]
Detects READY_FOR_TEST in ROADMAP.md
Boots dev server (npm run dev) and opens headless/headed browser via Playwright
Dispatches simulated 4-player simultaneous multi-touch/keyboard inputs
Inspects console logs, frame rate (FPS), and win condition states
If failures occur: Appends reproduction steps to QA_LOG.md and marks item FAILED
If verified: Marks item VERIFIED in ROADMAP.md
(Loop repeats until all roadmap items are verified)

7. Local Playtesting & Verification Protocol (http://localhost:5173/)
This section outlines the exact protocol, automated test script, and verification checklist for playtesting the application running on the local development server at http://localhost:5173/.
7.1 Automated Playtesting Harness (e2e/playtest.spec.ts)
Sub-Agent 2 (or a local developer) can execute this Playwright script against http://localhost:5173/ to validate canvas initialization, simulate simultaneous 4-player inputs, detect console errors, and confirm round completion:
import { test, expect } from '@playwright/test';
test.describe('1-4 Player Game Engine Verification', () => {
  const LOCAL_URL = 'http://localhost:5173/';
  test('Lobby loads with 60 FPS and 0 console errors', async ({ page }) => {
    const consoleErrors: string[] = [];
    page.on('console', msg => {
      if (msg.type() === 'error') consoleErrors.push(msg.text());
    });
    await page.goto(LOCAL_URL);
    await expect(page.locator('canvas')).toBeVisible();
    // Verify touch-action is disabled to prevent pinch-to-zoom interference
    const touchAction = await page.locator('canvas').evaluate(el => 
      window.getComputedStyle(el).touchAction
    );
    expect(touchAction).toBe('none');
    // Assert zero uncaught console exceptions
    expect(consoleErrors).toEqual([]);
  });
  test('Simulate 4-player simultaneous inputs and verify round transition', async ({ page }) => {
    await page.goto(`${LOCAL_URL}?game=tanks&players=4&autostart=true`);
    const canvas = page.locator('canvas');
    await expect(canvas).toBeVisible();
    const box = await canvas.boundingBox();
    if (!box) throw new Error('Canvas bounding box not found');
    // Dispatches simultaneous touch events across all 4 quadrants
    await page.touchscreen.tap(box.x + 40, box.y + 40);                         // P1: Top-Left
    await page.touchscreen.tap(box.x + box.width - 40, box.y + 40);             // P2: Top-Right
    await page.touchscreen.tap(box.x + 40, box.y + box.height - 40);            // P3: Bottom-Left
    await page.touchscreen.tap(box.x + box.width - 40, box.y + box.height - 40); // P4: Bottom-Right
    // Simultaneous keyboard inputs (W, O, C, M)
    await page.keyboard.down('KeyW');
    await page.keyboard.down('KeyO');
    await page.keyboard.down('KeyC');
    await page.keyboard.down('KeyM');
    await page.waitForTimeout(500);
    await page.keyboard.up('KeyW');
    await page.keyboard.up('KeyO');
    await page.keyboard.up('KeyC');
    await page.keyboard.up('KeyM');
    // Wait for victory state or sudden death countdown
    await page.waitForTimeout(3000);
    const isRunning = await page.evaluate(() => (window as any).__GAME_STATE__?.active !== false);
    expect(isRunning).toBeTruthy();
  });
});

7.3 Manual Playtesting Quality Checklist
When evaluating gameplay manually at http://localhost:5173/, verify the following criteria:
Touch Isolation (touch-action: none): Ensure fast, repeated tapping in corners does not trigger native browser double-tap zoom or viewport dragging.
Audio Context Initialization: Audio must cleanly unlock on the first user interaction without blocking UI rendering or triggering AudioContext was not allowed to start warnings.
Corner Ergonomics: Player buttons must remain at least 48x48 CSS pixels from screen edges with tactile visual feedback (ripples/flashes) on press.
Memory & Garbage Collection: Performing 10 consecutive round restarts must not cause memory accumulation or frame drop spikes (verify steady 60 FPS in Chrome DevTools Performance monitor).
AI Bot Balance: In 1-player mode against 3 bots, bots must demonstrate varied reaction times (Easy: 450ms, Normal: 250ms, Hard: 100ms) rather than infallible superhuman reflexes.
